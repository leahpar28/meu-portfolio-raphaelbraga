Boas práticas para o envio de commits:

**feat: (Feature)** Quando crio alguma funcionalidade nova 

    **Exemplo:** 
            git commit -m "feat: adiciona formulario de contato no HTML"

**fix: (Fix)** Quando se corrige bugs ou erros
    **Exemplo:**
            git commit -m "fix: corrige alinhamento do menu no CSS"

**docs: (Documentation)** Quando se mexe apenas na documentação, como por exemplo o **README**
    **Exemplo:**
            git commit -m "docs: atualiza instruções de instalação no README"

**style: (Style)** Quando as mudanças feitas são visuais, não altera como o projeto funciona, como por exemplo (Cores, Fontes, Organização de espaçamentos)
    **Exemplo:**
            git commit -m "style: altera cor de fundo do botao para azul"

**refactor: (Refactor)** Quando as mudanças feitas no código não mudam o que ele faz, mas o torna mais limpo ou mais rapidos "REFATORAÇÃO"

**chore: (chore)** Tarefas de "rotina" que não mexem no código do site em si (como atualizar uma ferramenta ou mudar uma configuração do projeto).

### obs: Use sempre letras minusculas, certo = fix | errado = FIX: ou Fix:
